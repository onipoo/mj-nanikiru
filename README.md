# 麻雀 何切る問題

受け入れ枚数に特化した何切る問題の練習アプリ。
問題は毎回その場で自動生成され、全打牌の受け入れ枚数を計算して正解を判定する。

## 使い方

`index.html` をブラウザにドラッグ＆ドロップするか、ダブルクリックで開くだけ。
サーバーもインストールも不要。

## 3つのモード

ヘッダーのタブで切り替える。

### 練習モード

自由に何問でも解ける。成績は記録しない。判定基準を通常／上級から選べる。

- 手牌の牌をクリックすると打牌を選択して判定
- 判定後は全打牌の向聴数・受け入れ枚数・受け入れ牌が表で出る
- Space キーで次の問題へ
- 向聴数を選べる（ランダム／聴牌／1／2／3シャンテン）

### チャレンジモード

麻雀の点棒に見立てた持ち点で競う。

- **25,000点**から始まり、**100,000点**でクリア
- 正解すると麻雀の点数表から引いた点数が入り、間違えると同じように失う
- **点棒が尽きるか、3回間違えたら終了**
- 制限時間は1問4秒（上級は7秒）

点数は実戦に近くなるよう、安い手ほど出やすい重みを付けた表から引く
（[`js/app.js`](js/app.js) の `SCORE_TABLE`）。期待値は子で約4,650点。

| 点数 | 出やすさ |
|---|---|
| 1000〜2600（1〜2翻） | 高い |
| 3900〜7700（3〜4翻） | 中 |
| 8000（満貫） | やや低い |
| 12000〜32000（跳満〜役満） | 低い〜稀 |

**親は1ゲームに1回だけ来る。** 子で正解するたびに抽選し、外れるほど確率が上がる
（1/3 → 1/2 → 3回目で確定）。親のあいだは正解するかぎり連荘し、間違えると流れて以降は子のまま。
親の点数表は子の1.5倍（役満48,000点）。

放銃した相手も麻雀に合わせている。自分が親なら他家は全員子。
自分が子なら3人のうち1人が親なので、**1/3の確率で親の点数表から失点**する。

間違えても即終了せず、正解を確認してから「続ける」で再開できる。
チャレンジ中は詳しい一覧表を出さず、正解と自分の選んだ手だけを見せる。

```js
const SCORE = {
  start: 25000,   // 開始時の持ち点
  goal: 100000,   // これ以上でクリア
  maxMisses: 3,   // これだけ間違えたら終了
};
```

### 作成モード

自分で14枚の手牌を組み立てて、最善手と全打牌の受け入れを調べられる。

- 下のパレットから牌を選ぶ（各牌4枚まで、合計14枚まで）
- 組み立て中の手牌をクリックすると1枚戻せる
- 14枚そろうと「正解を見る」が押せる
- 手牌を変えると解析結果は消える

## 上級モード（和了の速さ）

練習モードとチャレンジモードで、判定基準を切り替えられる。

| 判定基準 | 正解の決め方 |
|---|---|
| 受け入れ枚数（通常） | 向聴数が最も進み、その中で受け入れが最大 |
| 和了の速さ（上級） | **12巡以内に和了できる確率**が最も高い |

上級では次のような打牌が正解になる。

- **受け入れが狭くても、聴牌したときの待ちが広い打牌**
- **聴牌を崩す打牌（向聴戻し）** — 待ちが3〜4枚の聴牌より、
  1シャンテンに戻して受け入れを広げたほうが速いことがある

### 計算方法

**残り12巡のうちに和了できる確率**を求め、最も高い打牌を正解とする
（[`js/speed.js`](js/speed.js) の `TURNS`）。
見えていない牌は 136 − 14 = **122枚**。

**聴牌なら**「12巡のうちに待ち牌を引く確率」。
**1シャンテンなら**「i巡目に聴牌して、残りの巡で和了牌を引く」を全ての巡について足し合わせる。

聴牌したあとに待ちを広げられる場合は、その**待ち変え**も1回だけ見込む。
これを入れないと狭い聴牌を過小評価してしまう（下記）。

2シャンテン以遠は計算量が跳ね上がるため評価しない（表では「—」）。
鳴きは考慮せず、ツモのみで計算する。

### なぜ12巡で区切るか

はじめは打ち切りを設けず「和了までの平均ツモ回数」で比べていたが、
**実戦では有効でない向聴戻しが正解になってしまった。**

```
手牌: 666m 777m 888m 9m 44z 77z

              平均ツモ    8巡以内の和了率
向聴戻し 打北   24.51回     11.8%
聴牌維持 打6萬  24.60回     24.0%   ← 2倍の差
```

平均ツモ回数はほぼ同じなのに、8巡以内の和了率は2倍違う。
向聴戻しは聴牌するまで和了できないため**序盤の確率がゼロ**で、そのかわり後半に伸びる。
無限にツモれる前提だとこの後半の伸びが効きすぎるが、麻雀は18巡で終わるので回収できない。

指標を変えた効果は次のとおり。

| 指標 | ランダムな聴牌手牌で向聴戻しが正解になる割合 |
|---|---|
| 待ち変え未考慮の平均巡目 | 23.5% |
| 打ち切りなしの平均ツモ回数 | 11.7% |
| **12巡以内の和了率（現在）** | **6.3%** |

### 待ち変えの考慮

聴牌形の88.7%は、何かを引いて打牌すれば**待ちを広げられる**。
特に狭い聴牌では96%が該当し、平均46枚の牌が待ち変えに使える。
これを無視すると狭い聴牌を大きく過小評価する。

| 待ち | 待ち変えを無視 | 考慮した場合 |
|---|---|---|
| 2枚 | 41.00回 | 21.12回 |
| 4枚 | 24.60回 | 17.66回 |
| 8枚 | 13.67回 | 13.67回 |

なお「待ち変えの牌は手牌の近くにある」と考えて探索を絞ると**結果が変わってしまう**。
手牌に浮き牌があると、何を引いてもその浮き牌を切れば待ちが広がるため。
実装では「手牌と無関係な牌はどれを引いても結果が同じ」という性質で高速化している。

### 向聴戻しの出題頻度

ランダムな聴牌手牌のうち正解が向聴戻しになるのは6.3%だが、
生成器が「受け入れ基準と正解が違う手牌」を優先するため、
**実際に出題される聴牌問題では75%が向聴戻し**になる。

### 性能

確率分布の計算が入るため、受け入れ計算よりかなり重い。

| | 時間 |
|---|---|
| 解析1回 | 約430ms |
| 聴牌の問題生成 | 約5.8秒 |
| 1シャンテンの問題生成 | 約1秒 |

生成時間のほとんどは解析の積み上げ。1問作るのに解析が数回〜十数回走る。
メモ化（向聴数・待ち枚数・聴牌形）と、
「向聴戻しが有効なのは聴牌維持の待ちが5枚以下のときだけ」という絞り込みを入れている。

チャレンジ中は生成でJSが止まるため、開始前に15問まとめて作り置きし、
残りが5問を切ってから1問ずつ補充する。試行回数と制限時間もモードごとに変えている。

```js
const SPEED_TRIES = { practice: 4000, challenge: 400 };
CHALLENGE.speedTimeLimit = 7000; // 上級は7秒
```

## 問題の難しさ

難易度の選択肢は廃止した。難しさは
**正解と次善手の受け入れ枚数の差**で決まり、差が小さいほど見分けにくい。
モードごとの範囲は [`js/app.js`](js/app.js) 冒頭にある。

```js
const PRACTICE_GAP  = { min: 1, max: 4 };
const CHALLENGE_GAP = { min: 1, max: 4 };
```

差が大きい手牌ほど数が少ないため、範囲内を探すだけだと差1〜2枚の問題ばかりになる。
そこで狙った差を先に決め、見つからなければ順に条件を緩めている
（[`generateProblem`](js/analyze.js)）。

1. 狙った差ちょうどの手牌を探す
2. 見つからなければ範囲内ならよしとする
3. それでも見つからなければ上限を外す

**範囲を狭めすぎると逆効果になる。** 以前チャレンジを1〜2枚にしたところ、
条件に合う手牌が足りず手順3が25%発動し、かえって4枚差の問題が混ざった。
1〜4枚なら60問すべて範囲内に収まる。

同じ枚数差でも、**向聴数が深いほど難しい**点には注意（総受け入れ枚数が違うため）。

| 向聴数 | 差 | 正解 vs 次善 | 次善に対する差の割合 |
|---|---|---|---|
| 聴牌 | 2枚 | 7枚 vs 5枚 | 40% |
| 2シャンテン | 6枚 | 43枚 vs 37枚 | 16% |

## 出題する向聴数

「ランダム」なら 0〜3 から毎回選び直す。個別に指定もできる。
向聴数は手牌の繋がり具合でほぼ決まるため、目標ごとに配牌の
`nearRate`（すでに持っている牌の近くを引く確率）を変えている（`SHANTEN_NEAR_RATE`）。

| 向聴数 | nearRate | 生成時間の目安 |
|---|---|---|
| 聴牌 | 0.65 | 約290ms/問 |
| 1シャンテン | 0.45 | 約120ms/問 |
| 2シャンテン | 0.10 | 約120ms/問 |
| 3シャンテン | 0.00（完全ランダム） | 約45ms/問 |

4シャンテン以上は「孤立牌を含まない」条件とほぼ両立しないため出題しない。

## 判定基準と、その限界

正解は次の2段階で決めている。

1. 切ったあとの**向聴数が最も小さい**打牌を選ぶ（向聴戻しは正解にならない）
2. そのなかで**受け入れ枚数が最大**の打牌を正解とする

受け入れ枚数まで同じ打牌が複数ある場合は、そのすべてを正解とする。
結果表では向聴戻しの打牌のほうが受け入れ枚数が多く見えることがあるが、
向聴数が優先されるため正解にはならない。

聴牌の行の「受け入れ」は和了牌の枚数（待ちの広さ）を意味するため、
表では「◯枚（待ち）」と表示している。

**受け入れ枚数だけで決めた正解であり、実戦の最適打とは一致しないことがある。**
考慮していない要素:

- 打点（役・ドラ・リーチのみか満貫か）
- 待ちの良し悪し（良形テンパイか愚形テンパイか）
- 安全度（他家のリーチ・危険牌）
- 場況（残り巡目、点棒状況、他家の捨て牌）

受け入れ枚数は自分の手牌14枚だけを見えている牌として計算している
（他家の捨て牌やドラ表示牌による残り枚数の減少は考慮しない）。

## 出題される手牌について

ランダムな14枚をそのまま出すと「浮いた字牌を切るだけ」の自明な問題ばかりになるため、
以下の条件を満たす手牌だけを出題している。

- 孤立牌（1枚だけで、数牌なら前後2つ以内に仲間がいない牌）を含まない
- 同じ牌の4枚使いを含まない
- どれを切っても同じ、という手牌でない（正解は最大2種類まで）
- 次善手が向聴戻しでない（「正解以外を切ると向聴が戻る」実質一択の手牌を除く）
- 正解と次善手の受け入れ枚数の差がモードの範囲に収まる

## 計算エンジンについて

`js/shanten.js` は副露なしの門前手（13枚 or 14枚）に対応。
面子・搭子の分解を全探索して最小の向聴数を求める。和了は -1、聴牌は 0 を返す。

Node.js から直接呼べるので、動作確認は次のようにできる。

```bash
node -e "
const s=require('./js/shanten.js');
const A=require('./js/analyze.js');
// 123m456m789m123p1z → 聴牌(0) のはず
console.log(s.shanten(A.parseHand('123m456m789m123p1z')));
// 問題を1問生成して正解を表示
const p=A.generateProblem('hard');
console.log(p.hand.map((n,i)=>Array(n).fill(A.TILE_NAMES[i]).join('')).join(''));
console.log('正解:', p.answers.map(a=>A.TILE_LABELS[a]).join(' / '));
"
```
